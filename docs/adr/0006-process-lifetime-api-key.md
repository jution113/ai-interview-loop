# ADR-0006: 백엔드 실행 중 개인 API 키 유지

- **상태:** 수락됨(Accepted)
- **영역:** Backend
- **작성일:** 2026-11-24
- **작성자 / 참여자:** 주성천 / Codex

## 1. 배경 및 맥락 (Context)

- 면접 종료 후에도 최종 평가 재시도나 새 면접에서 같은 개인 API 키를 사용할 수 있어야 한다.

## 2. 결정 (Decision)

- 백엔드는 개인 API 키를 실행 중인 Spring Boot 프로세스의 메모리에만 보관한다.
- 한 번의 면접이 끝나거나 평가 생성에 실패해도 키를 유지한다. 사용자가 키를 직접 제거하거나 백엔드 프로세스가 종료되면 키가 사라진다.
- 코드, 로그, API 응답 및 영구 저장소에 키를 남기지 않는다. 브라우저에서 백엔드로 키를 전달하는 방법은 후속 검토 항목이다.

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 같은 백엔드 실행 중에는 키를 다시 입력하지 않고 평가를 재시도하거나 새 면접을 시작할 수 있다.

### 부정적 영향 및 트레이드오프

- 백엔드 재시작 후에는 키를 다시 입력해야 한다.

### 후속 조치

- 브라우저에서 백엔드로 키를 전달하는 방법은 [ADR-0001](0001-local-web-application.md)의 로컬 접속 구조와 함께 검토한다.
- 구현 후 면접 종료와 평가 실패 뒤 키가 유지되는지, 직접 제거하거나 백엔드를 재시작한 뒤 기존 키를 사용할 수 없는지 확인한다.
- 정상·오류 경로의 로그, API 응답, 영구 저장소에 키가 남지 않는지 검증한다.

### 검증 결과

- 미검증

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 장점 | 단점 | 채택 여부 및 판단 근거 |
|---|---|---|---|
| 면접 세션마다 키 제거 | 논의 기록 없음 | 새 면접이나 평가 재시도에서 키를 다시 입력해야 할 수 있다. | 대체. 백엔드가 실행 중이면 면접 종료 이후에도 키를 재사용할 수 있어야 한다. |
