# ADR-0005: 면접 기록의 로컬 영속 저장과 최종 평가 재시도

- **상태:** 수락됨(Accepted)
- **영역:** Common
- **작성일:** 2026-11-24
- **작성자 / 참여자:** 주성천 / Codex

## 1. 배경 및 맥락 (Context)

- 면접 종료 시점에만 기록을 저장하면 면접 후반부에 오류가 발생했을 때 이미 완료한 답변까지 잃을 수 있다. 문답 단위로 저장해 유실 범위를 줄이고 최종 평가의 실패가 면접 기록에 영향을 주지 않도록 한다.

## 2. 결정 (Decision)

- STT가 완료될 때마다 질문과 답변 텍스트를 로컬 영속 저장소에 저장한다. 최종 평가를 요청하기 전에 면접 기록과 평가에 필요한 기업·직무 자료 및 적용한 평가 기준의 저장을 완료한다.
- 원본 음성은 STT 처리 완료 후 삭제한다. API 키는 백엔드 프로세스 메모리에만 보관한다. [ADR-0006](0006-process-lifetime-api-key.md)
- 면접 진행 상태와 평가 생성 상태를 독립적으로 관리한다. 오류로 중단된 면접은 이미 저장한 문답을 열람할 수 있다. 중단된 면접 이어하기와 부분 평가는 MVP에서 제외한다.
- 정상 종료된 면접의 최종 평가 생성이 실패하면 저장된 기록으로 평가 생성만 재요청할 수 있다. 백엔드 재시작 뒤에도 기록을 열람하고 API 키를 다시 입력해 재요청할 수 있다.
- 사용자가 직접 종료한 면접은 자동으로 평가하지 않는다. 사용자가 피드백을 요청하면 종료 시점까지 저장된 문답을 바탕으로 생성한다.
- 면접자는 저장된 기록을 열람하거나 삭제할 수 있다.
- 평가할 답변이 0개이면 AI 채점·피드백을 호출하거나 점수를 표시하지 않는다. 저장된 기록이 있으면 보여주고 ‘평가할 답변이 없습니다’라고 안내한다.

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 평가 실패나 백엔드 재시작 후에도 저장이 완료된 문답과 평가 입력을 복구할 수 있다. 재시도는 새 면접이나 STT 재실행 없이 진행한다.

### 부정적 영향 및 트레이드오프

- 최종 평가 요청 전에 면접 기록과 평가 입력의 영속 저장을 완료해야 한다.

### 후속 조치

- 로컬 영속 저장 기술과 예외 처리 방식을 검토한다. 문답 저장 실패 시 진행 여부, 중복 평가 요청, 평가 중 기록 삭제와 늦게 도착한 결과 처리, 요청형 피드백 실패 후 재시도 조건이 포함된다.
- 진행 중 장애를 재현하고 백엔드 재시작 뒤 저장된 문답을 열람할 수 있는지, 중단된 면접에서 이어하기와 부분 평가가 제공되지 않는지 확인한다.
- 정상 종료 후 평가 실패를 재현한다. 백엔드를 재시작하고 키를 다시 입력한 뒤 저장한 평가 입력으로 평가만 재요청되는지 확인한다.
- 기록 저장을 마친 뒤 평가를 요청하는지, STT 완료 후 원본 음성이 삭제되는지, 영속 저장소에 키가 남지 않는지 확인한다.
- 수동 종료 시 자동 평가 호출이 없고 사용자 요청이 있을 때만 저장된 문답으로 피드백을 생성하는지 확인한다.
- 저장된 답변이 없거나 기획서의 평가 전 필터링 후 채점 대상이 0개이면 AI 채점·피드백을 호출하지 않고 점수 없이 안내하는지 확인한다. 저장된 기록이 있으면 열람할 수 있는지도 확인한다.
- 삭제한 기록을 다시 열람하거나 평가에 사용할 수 없는지 확인한다.
