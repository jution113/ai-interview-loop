# ADR-0009: Spring Boot에서 프런트엔드 정적 리소스 제공

- **상태:** 수락됨(Accepted)
- **영역:** Common
- **작성일:** 2026-11-25
- **작성자 / 참여자:** 주성천 / Codex

## 1. 배경 및 맥락 (Context)

- MVP는 사용자 PC에서 실행하는 웹 앱이다. [ADR-0001](0001-local-web-application.md)
- 프런트엔드와 백엔드 소스는 단일 저장소의 별도 디렉터리에서 관리한다. [ADR-0002](0002-monorepo.md)

## 2. 결정 (Decision)

- MVP 사용자 실행 시 Spring Boot 프로세스 하나가 화면의 정적 파일과 백엔드 API를 같은 로컬 출처에서 제공한다.
- 화면 렌더링과 사용자 조작은 브라우저에서 실행되는 프런트엔드 코드가 맡는다. 서버 처리가 필요하면 브라우저가 같은 출처의 Spring Boot API에 HTTP 요청을 보낸다.
- 프런트엔드 소스는 `frontend/`에서 관리한다. 프런트엔드 빌드가 있는 경우 결과물을, 빌드 없이 제공할 수 있는 경우 정적 파일을 Spring Boot가 제공할 리소스에 포함한다.

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 사용자 기동 절차가 한 서버로 줄어들고, 브라우저에서 API를 같은 출처의 상대 주소로 호출할 수 있다.
- 화면과 API의 HTTP 경계를 유지하므로 공개 서비스에서 독립 배포가 필요해질 때 프런트엔드 제공 위치를 다시 검토할 수 있다.

### 부정적 영향 및 트레이드오프

- 프런트엔드 파일을 Spring Boot에 포함하는 구성이 필요하다. 개발 중 화면 변경을 반영할 때 구성에 따라 파일 복사나 재빌드가 필요할 수 있다.

### 후속 조치

- 로드맵 1.2에서 서버 한 번 기동으로 `localhost`에서 설정 화면과 정적 리소스를 열 수 있는지 확인한다.
- 프런트엔드 프레임워크와 개발 전용 서버 사용 여부는 필요에 따라 별도로 검토한다.
- 공개 웹 서비스 전환 시 인증, 사용자별 데이터 격리, API 키 보관 정책을 별도로 검토한다. 프런트엔드 독립 배포 여부도 운영 요구에 따라 판단한다.

### 검증 결과

- 자동화 검증에서 Spring Boot 한 번 기동으로 설정 화면과 정적 리소스에 접근했다(TC-01). 로컬 Chrome에서 모의 설정 제출이 통과했다(TC-02). 개발자가 로컬 화면, 키보드 탐색과 입력 안내, 모의 제출을 직접 확인했다(TC-10~12 통과).

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 장점 | 단점 | 채택 여부 및 판단 근거 |
|---|---|---|---|
| Spring Boot가 화면과 API를 함께 제공 | 사용자 기동이 단순하고 브라우저에서 같은 출처로 API를 호출할 수 있다. | 정적 리소스 포함 구성이 필요하고 개발 중 변경 반영에 재빌드가 필요할 수 있다. | 채택. 로컬 MVP의 실행과 검증 절차를 단순화한다. |
| 프런트엔드 서버와 Spring Boot를 별도로 실행 | 독립 빌드가 가능하고 개발 서버의 자동 새로고침을 활용하기 쉽다. | 두 서버를 기동해야 하며 포트가 다를 때 API 프록시 또는 출처 허용 설정이 필요할 수 있다. | MVP 사용자 실행 방식으로 미채택. 개발 전용 서버는 필요해질 때 검토한다. |
