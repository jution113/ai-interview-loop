# ADR-0004: 개인 API 키의 세션 기반 임시 보관

- **상태:** 대체됨(Superseded by [ADR-0006](0006-process-lifetime-api-key.md))
- **영역:** Backend
- **작성일:** 2026-11-24
- **작성자 / 참여자:** 주성천 / ChatGPT / Codex

## 1. 배경 및 맥락 (Context)

- 사용자가 개인 API 키를 제공한다. 민감한 인증 정보를 영구 보관하는 데 따른 관리 부담을 줄이기 위해 키의 보관 범위와 수명을 정한다.

## 2. 결정 (Decision)

- Spring Boot 백엔드는 사용자의 개인 API 키로 외부 AI API를 호출한다. 키는 해당 세션 동안 백엔드 메모리에 임시 보관하고 세션 종료·삭제 시 제거한다. 코드, 로그, API 응답, 영구 저장소에 키를 남기지 않는다. AI 호출 비용은 사용자가 부담한다.

- 브라우저에서 백엔드로 키를 전달하는 방법, 세션 만료 기준, AI 공급자는 후속 설계에서 검토한다.

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 민감한 인증 정보를 영구 보관하는 데 따른 관리 부담을 줄인다.

### 부정적 영향 및 트레이드오프

- 당시 결정에서는 세션 종료·삭제 또는 백엔드 재시작 후에 키를 다시 입력해야 했다.
- 실제 AI 기능에는 개인 API 키와 외부 AI API에 접근할 수 있는 네트워크 연결이 필요하다.

### 후속 조치

- 이 결정은 [ADR-0006](0006-process-lifetime-api-key.md)으로 대체됐다. 키의 수명과 현재 검증 계획은 해당 ADR을 따른다.
- 당시에는 새로고침, 탭 닫기, 유휴 만료, 세션 삭제, 백엔드 재시작 시 키의 유지·제거 조건과 환경 변수 방식의 최종 비교를 후속 검토로 두었다.
- 평가 실패 뒤 키 재입력 문제는 [ADR-0005](0005-interview-record-and-evaluation-retry.md)와 함께 논의했다. 키 전달 방식은 [ADR-0001](0001-local-web-application.md)의 로컬 접속 구조와 함께 검토하기로 했다.
- 당시 검증 계획에는 가짜 키를 사용한 세션 종료·삭제 후 재사용 방지와 정상·오류 경로의 로그, API 응답, 영구 저장소 점검이 포함됐다. 키 설정 절차는 README에 기록하기로 했다.

### 검증 결과

- 미검증. 이 결정은 대체됐으며 현재 정책의 검증은 ADR-0006에서 다룬다.

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 장점 | 단점 | 채택 여부 및 판단 근거 |
|---|---|---|---|
| 브라우저 저장 | 논의 기록 없음 | 브라우저 스크립트를 통한 키 노출 위험을 고려해야 한다. | 미채택. 당시에는 백엔드 세션 메모리 보관을 선택했다. |
| DB 암호화 저장 | 논의 기록 없음 | 암호화 키 관리가 추가된다. | 미채택. MVP에 영구 저장이 필요하지 않았다. |
| 환경 변수 | 로컬 실행에서 가능한 방식이다. | 일반 사용자의 설정 편의성을 검토해야 한다. | 당시 최종 비교를 후속 검토로 남겼다. |
