# ADR-0008: 면접 진행 상태의 백엔드 확정

- **상태:** 수락됨(Accepted)
- **영역:** Common
- **작성일:** 2026-11-24
- **작성자 / 참여자:** 주성천 / Codex

## 1. 배경 및 맥락 (Context)

- 면접 중 타이머 만료와 사용자 버튼 클릭이 겹칠 수 있다. 같은 답변이 중복 접수되거나 질문이 두 번 넘어가지 않도록 상태 전환을 확정할 책임을 정한다.

## 2. 결정 (Decision)

- 브라우저는 면접 화면과 타이머를 담당한다. 타이머 만료와 사용자의 조작을 백엔드에 전달하고, 백엔드가 확정한 진행 상태를 화면에 반영한다.
- 백엔드는 현재 질문, 답변 접수, 다음 질문, 면접 종료를 확정한다. 같은 답변의 종료 이벤트가 겹치면 답변 접수와 다음 상태 전환을 한 번만 처리한다.
- 면접 진행 상태와 평가 생성 상태는 독립적으로 관리한다. [ADR-0005](0005-interview-record-and-evaluation-retry.md)

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 백엔드 한 곳에서 중복 접수와 중복 상태 전환을 판단할 수 있다.

### 부정적 영향 및 트레이드오프

- 브라우저가 새로고침되거나 백엔드 응답이 지연될 때 화면을 확정된 상태와 동기화하는 흐름이 필요하다.

### 후속 조치

- 상태 전이와 이벤트 전달 방식을 구현 전에 검토한다. 타이머 만료와 버튼 클릭이 겹치는 경우, 처리 중 수동 종료, 화면 새로고침 시 상태 동기화를 확인한다.
- 백엔드 재시작 후 기록 복구와 중단된 면접의 이어하기 범위는 ADR-0005를 따른다.

### 검증 결과

- 미검증

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 장점 | 단점 | 채택 여부 및 판단 근거 |
|---|---|---|---|
| 브라우저가 면접 진행 상태를 확정 | 타이머와 UI를 연결하기 쉽다. | 백엔드에서 답변을 처리하는 동안 종료나 재시도가 발생하면 브라우저와 백엔드의 상태를 맞춰야 한다. | 미채택. 답변 접수와 상태 전환의 중복을 백엔드 한 곳에서 제어하는 방식을 택했다. |
