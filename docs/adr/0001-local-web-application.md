# ADR-0001: 로컬 실행형 웹 애플리케이션 채택

- **상태:** 수락됨(Accepted)
- **영역:** Common
- **작성일:** 2026-11-24
- **작성자 / 참여자:** 주성천 / ChatGPT / Codex

## 1. 배경 및 맥락 (Context)

- AI Interview Loop는 개인 면접 연습용 웹 애플리케이션이다. MVP에서 프런트엔드와 백엔드를 실행할 위치, 브라우저 접속 방식을 정한다. 공개 서버 운영 비용과 타인의 API 키·지원 자료를 직접 관리하는 부담을 줄이고, 기존 Spring Boot 프로젝트를 활용한다. 파일 첨부, 마이크 입력, 음량 측정, 타이머는 브라우저에서 제공한다.

## 2. 결정 (Decision)

- Spring Boot 백엔드와 웹 프런트엔드를 사용자 PC에서 실행한다. 사용자는 브라우저에서 `localhost`로 접속한다.
- 공개 웹 서비스 배포와 데스크톱 응용 프로그램 패키징은 MVP 범위에서 제외한다.
- 프런트엔드 서빙 방식은 후속 설계에서 검토한다.

## 3. 결과 및 영향 (Consequences)

### 긍정적 영향

- 공개 서버 운영 비용과 타인의 API 키·지원 자료를 직접 관리하는 부담을 줄이고, 기존 Spring Boot 프로젝트를 활용할 수 있다.

### 부정적 영향 및 트레이드오프

- 사용자가 자신의 PC에서 실행 환경을 준비해야 한다.

### 후속 조치

- **우선순위:** 높음. 설정 화면과 로컬 접속 구조 설계 전에 검토한다.
- Spring Boot가 프런트엔드 빌드 결과를 제공하는 방식과 별도 로컬 프런트엔드 서버를 실행하는 방식을 기동 명령 수, 브라우저 접속 주소, API 호출 경로를 기준으로 비교한다.
- 백엔드 수신 범위를 검토한다. 서로 다른 포트를 사용한다면 허용할 브라우저 출처를 [ADR-0006](0006-process-lifetime-api-key.md)의 키 전달 방식과 함께 검토한다.
- 실제 로컬 기동 및 접속 절차는 README에 기록한다.
- 구현 후 백엔드와 프런트엔드의 로컬 기동, 브라우저 접속, 마이크 권한을 확인하고 결과를 연결한다.

### 검증 결과

- 미검증

## 4. 검토한 대안 (Alternatives Considered)

| 대안 | 장점 | 단점 | 채택 여부 및 판단 근거 |
|---|---|---|---|
| 공개 웹 서비스 | 논의 기록 없음 | 서버 운영 비용과 타인의 키·개인정보 관리 부담이 생긴다. | 미채택. 해당 운영·관리 부담을 고려해 MVP에서 제외했다. |
| 데스크톱 응용 프로그램 | 논의 기록 없음 | 운영체제별 패키징 작업이 추가된다. | 미채택. 현재 요구사항을 웹에서 충족할 수 있다. |
